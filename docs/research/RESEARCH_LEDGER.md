## 7. Recorded disagreements (unresolved)

1. **"Guaranteed" structured output.** Outlines (R-17) claims guaranteed structure; llama.cpp
   (R-15) documents that unsupported schema features are *silently skipped*. Both can be true:
   the guarantee covers only the converted subset. We therefore treat all constraint engines
   as syntax-only and validate independently.
2. **Strictness as reliability.** OpenAI (R-16) presents Structured Outputs as removing the
   need to validate formatted responses, while the same documentation (R-24) documents
   refusals that do not follow the schema, and R-19 measures reasoning degradation from strict
   formats. Unresolved; our response is to keep the constrained object minimal and validate
   anyway.
3. **Idempotent retry vs single-use authority.** Stripe (R-35) returns the first stored result
   on retry; RFC 6749 (R-34) requires the *denial* of a reused authorization code. These are
   opposite behaviours for the same event. We choose denial for authority (permits) and record
   idempotency as a requirement to be negotiated for the collaborator's mutating endpoints.
4. **Latency reporting.** BFCL v1 reports batched throughput per entry; Tene (R-48) and
   OpenTelemetry (R-49) require per-request percentiles. We follow the latter.
5. **Determinism.** OpenAI (R-50) implies near-determinism when the fingerprint matches;
   Thinking Machines (R-28) demonstrates temperature-0 nondeterminism from batch-size
   variation, which seeds cannot fix. We follow R-28: no equality assertions.
6. **OWASP edition drift.** "Insecure Plugin Design" (2023/24) does not exist in the 2025
   list; LLM05 was renamed "Improper Output Handling"; a 2026 edition was published
   2026-08-03. We cite the dated 2025 entry pages we actually read (R-26, R-27) and do not
   claim "current best practice" without a date.
